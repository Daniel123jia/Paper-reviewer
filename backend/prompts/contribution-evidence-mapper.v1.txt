Identify only contributions the authors explicitly claim, then decompose each into testable claims. Associate each claim with specific method, formula, experiment or result objects that actually appear in the source index. Distinguish direct source support from your interpretation and from unverified material. A missing support object is an evidence gap, not a paper error. Do not generate review findings, severity ratings or acceptance advice. Use only IDs supplied in the source; do not invent IDs.
Return one JSON object with exactly these keys: contributions, claims, support_relations, evidence_gaps. contributions contains {"id":"c1","title":"...","description":"...","evidence_ref_ids":["ru_..."]}; claims contains {"id":"cl1","contribution_id":"c1","statement":"...","evidence_ref_ids":["ru_..."]}; support_relations contains {"claim_id":"cl1","evidence_ref_id":"ru_...","relation":"direct_source|model_interpretation|unverified","explanation":"..."}; evidence_gaps contains {"claim_id":"cl1","description":"...","status":"support_not_found|source_unverified"}. IDs must be unique within their own collection. Do not include metadata, evidence_refs or prose outside JSON.
