# 全文审稿 MVP

网页入口为“全文审稿”，也可直接打开 `/?view=compact`。本地上传不触发模型。选择已解析的论文、确认本地费用并开始后，任务最多派发两次。第一次输出中文结构化初稿，第二次收到同一份全文和初稿，逐条记录保留、修订或删除及其理由，给出完整修订报告。没有最低问题数量。两个步骤都保存结果；只有完成核查的版本开放 Markdown/PDF 导出。

## 运行和复验

使用仓库 README 中的后端 Python 环境、前端 npm 依赖、Chromium 和 Pandoc。建议在独立目录运行。启动后端和前端的命令如下（分别在仓库根目录和 frontend 目录执行）。

```sh
PAPER_REVIEW_DATA_DIR=/path/to/new-private-data python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
npm run dev
```

付费功能使用后端既有的 OPENAI_MODEL、OPENAI_API_KEY、OPENAI_BASE_URL 配置；浏览器不接触密钥。首次启动每篇内容哈希只创建一个任务，重启、重复确认和刷新均不会重放。已有 C1 冻结运行模式没有该接口。界面在任务启动前展示两次请求的合计本地费用上限；每次最多预留 128,000 输入单位（以输入 UTF-8 字节保守估算）及 8,000 输出 Token。以 0.80 / 4.00 站内额度每百万 Token 估价，合计规划 0.27。实际输入输出取供应商返回 Usage；模型不符或 Usage 未知即停止。输出过长、结构无效、证据无法匹配或核查不全都会停止并保留已完成的初稿，不追加修复请求。

固定验收 PDF 为 Yoon Kim, EMNLP 2014，SHA-256 为 `a996da85e0abf6bb1a16cebbb82137af5ca8c16cadc81bc41358829a3687a6cf`。使用本地已获授权的 PDF。下例仅使用 Fake SDK。

```sh
export KIM_2014_PDF=/absolute/path/to/Kim2014.pdf
python -m pytest -q backend/tests/test_compact_review.py
(cd frontend && npm run build)
python -m scripts.compact.demo "$KIM_2014_PDF" /path/to/new-demo-directory
```

浏览器验收命令使用隔离的临时数据库与回环端口，替换 SDK 边界，真实上传、持久化、回查、下载并退出。输出实际浏览器截图、两份导出、初稿、修订映射及模拟调用审计。报告中的标记表明正文由确定性测试夹具产生。

## 证据与使用边界

两遍均提交 P1 抽取的所有文字块及其 PDF 页码、章节映射和 Evidence ID，附表格候选行、公式候选转录、图注及解析限制。图像像素和人工核验未进入模型。过大的材料会被拒绝，不截去尾页。两个 Prompt 与输出契约在 backend/compact_review.py；普通审稿的鉴权、流式 Usage 核销、预算熔断和 SDK 零重试仍生效。检查器用 Unicode 和空白归一化比对每个问题的引文与指定块，并验证全部初稿问题的修订映射。引文存在只能证明文本定位；其论证、解释及技术含义仍应由读者判断。报告里的 Evidence ID 可点击，打开 PDF 页并高亮对应块。

## 与 ChatGPT 网页版的独立盲评

1. 使用上述 PDF、同一份中文审稿要求、仅限原文的材料政策。由用户或独立 ChatGPT 会话取得网页版首次完整输出。保存模型标识（若界面可见）、日期、输入及原始报告。MVP 同样封存首次真实输出及账本；两边都不事后润色。
2. 由第三人将两份报告随机标为 A/B，隐藏产品名、排版特征与费用。由熟悉 NLP 的读者先独立列出值得审查的核心主张，再读两个报告并逐条回到原文。可接受来源定位的不同写法。重复意见归并；不以条数定优劣。
3. 对下列六项分别给 0、1、2 分（0 为缺失或实质错误，1 为部分成立，2 为准确且有具体依据），每项记下原页、短理由与较优报告。无法判断记“待核”，不按零分处理。

| 项目 | 评价问题 |
|---|---|
| 理解准确性 | 是否正确区分词表示策略、模型结构及评价条件？ |
| 关键问题发现 | 是否抓住真正影响论文结论的技术问题？作者已答的问题有几条？ |
| 深度 | 是否解释问题如何影响推断，并考虑反证与替代解释？ |
| 证据准确性 | 每条 Major 的引文、页码和结论是否相符？有几条缺证或误读？ |
| 可操作性 | 作者能否据此提供具体、范围合理的补充或修改？ |
| 实际价值 | 真实审稿人会保留、修改或删除哪些意见？遗漏了什么？ |

4. 单列可确认的虚构引文、错误归因、数据误读和重复意见数量，并记录可核查意见总数。任何实质性错误指控都须单独裁定，不能被总分掩盖。揭盲后并列呈现结论与分歧。单篇结果仅支持该论文个案；缺少网页版报告或专家检查时保留未评状态。Fake SDK 只用于工程验收。

下一次真实验证需单独确认所用模型与端点、单次预算、已知网络中断风险及使用固定论文的授权。封存真实调用次数、模型标识、耗时、已知 Token、费用估算与供应商账单可得性，再进行上述盲评。
