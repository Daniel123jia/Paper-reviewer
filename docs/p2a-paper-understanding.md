# P2-A: N1–N3 paper understanding

This branch starts from P1 squash merge `12a55b4d836084cbc2a07790596f6561043b6673`. The existing sampled review, candidate screening, countercheck, report, Evidence API, PDF reader and export paths are unchanged. The new API is backend only.

## P2-A.1 additions

New runs write Schema 1.1; Schema 1.0 results remain readable. `PaperProfile.source_conflicts[]` records only unresolved within-paper differences, with both source ID lists, the shared experimental configuration and a verification question. A consistency model call sees numerical source excerpts and N2 result facts. It is instructed to compare the same model, dataset, setting and metric, and to leave different experiments separate. Its output is a lead for PDF verification, not an accusation of error.

N3's global normalizer sees the PaperProfile author-claimed contributions as paper-level anchors, every part contribution and claim, plus the relevant N2 facts. It groups equivalent contributions and claims; the server validates that the groups form complete partitions, splits any proposed claim group crossing distinct contributions, creates deterministic content-hash IDs, unions distinct source references and rebuilds relations. Ancillary availability statements may be excluded from the core contribution map by an explicit model grouping decision while remaining in PaperProfile. A local `support_not_found` is removed only when the normalizer explicitly matches that same evidence need to a direct original-source relation from another part of the merged claim; the server checks the relation and part provenance. Independent formula, table and experiment gaps survive general text support. Repeated unresolved descriptions for one claim are deduplicated, and uncertain local gaps remain `source_unverified`. N2 source leads can become `unverified` relations with a `source_unverified` gap. A remaining `support_not_found` means the supplied full Source Bundle and N2 facts offered no support lead; it explicitly requires PDF verification before treating source absence as a paper omission.

The N3 input now uses larger 9,000-character parts and sends only source-local profile scalar facts; all reading units still enter N2 and N3. `P2A_MAX_CALLS`, `P2A_MAX_INPUT_TOKENS`, `P2A_MAX_OUTPUT_TOKENS`, and `P2A_MAX_DURATION_MS` configure per-run limits (defaults: 32, 300,000, 100,000, 1,800,000). Before each call the budget reserves an input estimate and 4,096 output tokens when usage is unknown. Failed calls keep token fields null, count under `unknown_token_calls` in usage summaries, and consume estimated budget; they are never represented as known zero-token calls. An exhausted budget leaves completed prior stages available and sets the run status to `budget_exceeded`.

## Contracts and execution

`backend/p2a_schema.py` defines version `1.1` Pydantic contracts and reads prior `1.0` results. All three results contain `document_id`, `source_bundle_id`, `review_run_id`, `prompt_version`, `schema_version`, `model_identifier`, `input_coverage`, and `execution_status`. N1 `ReviewPlan` holds paper type, domain, paradigm, applicable/priority/excluded review dimensions, and required/missing materials. N2 `PaperProfile` holds the research problem, motivation, author-claimed gap, method and components, assumptions, setup, datasets/metrics, results, contributions, conclusions, author-stated limitations, source gaps and canonical evidence references. N3 `ClaimEvidenceMap` holds `Contribution`, `Claim`, `SupportRelation`, `EvidenceGap`, and canonical `EvidenceReference` objects.

The engine uses P1 `reading_units[]` in order. A short input is read in one call. Longer input is split without omitting units. N2 asks the model for a concise global reconciliation of the four core narrative facts, then deterministically unions every part-level fact list and its source IDs. If that global call fails, all part-level lists are retained and a visible source gap states that core narrative synthesis fell back to the first part. N3 maps claims in smaller source parts with the complete profile available to the pipeline; each call receives the profile facts whose source IDs map to that part, plus author-claimed contributions. Global consolidation groups semantic equivalents from structured facts, assigns stable IDs, and preserves relations. `input_coverage` records which units entered the pipeline, not semantic completeness of the final answer. N1 sees a representative reading sample and the full section inventory for planning; the prompt explicitly forbids treating unsampled sections as absent. No output is a review finding. Model-supplied source IDs are resolved server-side against actual Source Bundle objects. Validation rejects missing IDs, foreign snapshots or documents, duplicate contribution/claim IDs, broken relations, uncited profile facts, and claims with neither a support relation nor an explicit evidence gap. A limited parser input produces `execution_status=limited`; it cannot be promoted to verified by the model.

Prompt templates: `paper-type-planner/v1`, `paper-understanding/v1`, `contribution-evidence-mapper/v2`, `source-consistency/v1`, and `contribution-normalizer/v2`. They contain no Shaw-specific answers. Formula, table and figure status is presented as unverified unless P1 has independent human reference; the profile must carry unresolved source gaps.

## API and storage

`POST /api/documents/{document_id}/understanding-runs` starts an isolated background run (optional `target_journal`, `special_requirements`). `GET /api/understanding-runs/{run_id}` returns status, completed stage results and call metadata. Each call trace is saved immediately; a completed N1 remains available if N2 fails. `GET /api/understanding-runs/{run_id}/source-bundle` retrieves the exact bundle snapshot used by that run. These routes use the existing `/api/*` session protection. The new SQLite tables are independent of `review_runs` and never feed the historical review algorithm. On startup, interrupted P2-A runs are marked failed. Existing SQLite files gain only the new tables; an early development version of the P2-A table gains `source_bundle_json` via additive migration. Existing usage summaries also include these calls under `understanding`.

The local `data/` directory and `.env.local` remain gitignored. The run table stores the Source Bundle snapshot and validated results in that local database. The call table stores prompt version, requested/returned model IDs, token counts, elapsed time, status and sanitized error class; it does not store API keys, full model input or raw response. Detailed real-test inputs and raw outputs are saved under a private, mode-0700 `data/p2a-evaluation/runs/` directory with mode-0600 files and are not uploaded to GitHub. The local evaluation runner redacts the configured API key before writing any request or response. Operators must set an access token and a retention policy before exposing this local service beyond the trusted machine; automatic production data expiry is not implemented in P2-A.

## Verification and limitations

Mock tests exercise all three contracts, full-unit coverage, long-input synthesis, reference and snapshot validation, retry/failure paths, secret-free error traces, API persistence and baseline isolation. Real-model quality must be evaluated separately. The [public Shaw 2018 PDF](https://arxiv.org/pdf/1803.02155) and a held-out [public DistilBERT 2019 PDF](https://arxiv.org/pdf/1910.01108) are used for local end-to-end runs; neither paper is embedded in prompts. The measured runs and human academic checks are in [p2a-real-evaluation.md](p2a-real-evaluation.md). Public structured output examples are in [Shaw](examples/p2a-shaw2018) and [DistilBERT](examples/p2a-distilbert2019). These examples contain validated structured results, not actual model inputs or raw responses.

P1's geometric reading order, section boundaries and technical object transcription remain candidates. A `blocked` whole-paper scope stops before any model call; `needs_review` propagates as `limited`. N2/N3 cannot certify equation, table or figure correctness. A missing object in parser output is a source gap, not evidence that the authors omitted it. External literature validation, multi-dimensional issue generation, counterchecks, severity, and reports remain outside P2-A.

The public Shaw PDF produced 167 reading units. Whole-paper section readiness is `needs_review` due to ambiguous order, incomplete section assignment/source mapping, and absent human reading/page references. Table 1 has incomplete structure; Tables 2 and 3 are detected but unverified; equations (1)–(5) are transcription candidates; Figure 1 needs visual review. The model may use these as leads but must not present their structure or meaning as independently verified. Table 3's candidate rows are `Yes/Yes/25.8`, `No/Yes/25.8`, `Yes/No/25.3`, `No/No/12.5`; those row/column assignments are not promoted to verified evidence by P2-A.
