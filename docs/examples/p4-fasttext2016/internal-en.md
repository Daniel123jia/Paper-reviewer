## Points Requiring Clarification

### 1. Clarify the calculation and training scope of the sentiment-classification speedup

In the sentiment-classification results and training-time discussion, please clarify which dataset, comparator, and model configuration support the stated at-least-15,000-fold speedup, and whether this ratio compares individual epochs or complete training runs. The classification timing-table caption explicitly describes single-epoch measurements, whereas the authors report training fastText for 5 epochs to obtain the classification accuracies. The authors also disclose that the convolutional baselines use a GPU while fastText uses a CPU with 20 threads, and acknowledge that implementation changes could accelerate a baseline. These disclosures provide useful context, but do not establish the complete-training ratio at the reported accuracies. Please identify the configurations paired across the accuracy and timing results, state the baseline epoch counts and stopping criteria, and show the speedup calculation with its timing denominator. If the available results establish a complete-training comparison, please report that ratio using the corresponding training schedules. Otherwise, please explicitly limit the classification speedup statement to single-epoch timing under the disclosed hardware, threading, and implementation conditions. This clarification would allow readers to distinguish the reported per-epoch advantage from the time required to obtain the reported predictive performance.

Paper locations: PDF page 1; PDF page 2; PDF page 3; PDF page 4; Table 2, PDF page 3.

Suggested author response: Identify the dataset, comparator, matched model configurations, and timing denominator underlying the stated speedup. Provide the baseline training schedules and the corresponding complete-training calculation if available; otherwise, qualify the classification claim as a comparison of single-epoch timings under the disclosed execution conditions.

### 2. Clarify how to reproduce the dataset splits for tag prediction

In the “Dataset and baselines” description of the experiment predicting image tags from titles and captions, the authors describe filtering the corpus, report aggregate split sizes, and promise a script to recreate the dataset. The manuscript also provides a fastText repository link and states that code will be published. These statements provide possible routes to reconstruction, but the supplied material does not establish whether the original task description or accompanying materials specify exact record IDs, a deterministic split-assignment rule, or a random seed. Reproducing aggregate split sizes alone would not establish that the same records were used for training, validation, and testing, which matters for reproducing the reported evaluation. Please identify and cite the reconstruction materials and their relevant version, and indicate where they define the record assignments. If assignment is algorithmic, please specify the rule, any required input ordering, and any random seed; if these details are already documented, a precise reference would resolve this clarification.

Paper locations: PDF page 1; PDF page 4; PDF page 5.

Suggested author response: Provide a versioned reference to the dataset reconstruction materials and identify the exact record lists or deterministic assignment procedure, including any required input ordering and random seed. If these details are absent from the existing materials, document them.

### 3. Clarify the expected-cost interpretation of Huffman hierarchical softmax training

In the passage introducing Huffman hierarchical softmax, the authors state a reduced training complexity, but the available excerpt does not specify whether this is an expected cost under the frequencies used to construct the tree. The adjacent discussion of node depth and inference does not resolve that interpretation. This distinction matters because interpreting the training cost requires knowing how target path lengths are averaged and whether the training-target distribution matches the tree-construction frequencies. Please clarify the intended meaning of the training-complexity statement, identify the counts used to construct the Huffman tree, and explain how training targets are selected, including the treatment of documents with multiple tags in the tag-prediction experiments. If the statement describes an expected cost, please state the averaging distribution and its relationship to the tree-construction frequencies; if another interpretation is intended, please specify the relevant assumptions. A brief clarification or a pointer to an existing explanation would help readers interpret the authors' efficiency claim.

Paper locations: PDF page 2; PDF page 4.

Suggested author response: Clarify whether the stated training complexity is an expectation, specify the frequencies used to build the Huffman tree and the distribution used to select training targets, and explain how these relate when documents have multiple tags. Identify any existing passage that already supplies these assumptions, or revise the complexity discussion to make them explicit.

### 4. Clarify the scope of averaged representations and the basis for the word2vec contrast

In the conclusion, the authors state that their word features can be averaged to form good sentence representations and contrast this property with unsupervised word2vec vectors. The method description explains that the averaged representation feeds a linear classifier trained using document labels, and the reported evaluations concern supervised sentiment classification and tag prediction. This context supports interpreting the usefulness of the representations within the evaluated supervised classifiers. Please make that scope explicit and identify the evidence or intended qualification for the contrast with averaged unsupervised word2vec vectors. This distinction matters because readers could otherwise interpret the conclusion as establishing a general comparative advantage of the representations or their averaging operation beyond the evaluated setting. If the comparison is supported elsewhere in the paper, please point to the relevant evidence and clarify its conditions; otherwise, qualify the contrast and describe broader reuse as a potential application.

Paper locations: PDF page 1; PDF page 2; PDF page 3; PDF page 4; PDF page 5.

Suggested author response: Revise the conclusion to tie the demonstrated usefulness of averaged features to the evaluated supervised classifiers. Identify the supporting comparison or citation for the word2vec contrast and explain its scope, or qualify that contrast if it is intended as a narrower observation. Distinguish potential reuse from demonstrated reuse.

Please identify any existing measurements and their locations, and explain the experimental scope over which the observed scaling is supported. If no such measurements are reported, please state that limitation and qualify the scaling discussion accordingly.

### 7. Clarify system-level efficiency and attribution of component-specific speedups

Does the complete paper distinguish end-to-end system efficiency from speed attributable to particular algorithmic components? This question concerns the sentiment training-time comparisons, the Vowpal Wabbit implementation comparison, and the tag-prediction training and inference results. The authors already discuss the advantage of their tailored implementation, explain the computational rationale for hierarchical softmax and tree-based inference, and disclose execution configurations, including matched thread counts for the tag-prediction comparison. These details provide useful context for interpreting the reported efficiency. However, the supplied passages do not establish how much of the measured advantage can be attributed separately to algorithmic choices, implementation, or parallelism. This distinction matters because comparisons between complete systems support a different interpretation from controlled measurements of individual components. Please clarify which efficiency claims describe the evaluated systems as a whole and which are supported by comparisons that isolate a particular component. For the relevant comparisons, identify the timing boundaries and matched experimental conditions, and distinguish per-epoch timing from complete training time or time to comparable predictive performance. If existing controlled comparisons address component attribution, please point to them. Where such attribution has not been measured, qualify the interpretation of the speed claims accordingly.

Suggested author response: Clarify the scope of the efficiency claims, specify timing boundaries and relevant experimental controls, and cite any existing comparisons that isolate implementation, parallelism, or inference strategy. Where the evidence supports only a system-level comparison, state that limitation explicitly.

### 8. Clarify the corpus scope used for frequency filtering

In the “Dataset and baselines” paragraph describing tag prediction from image titles and captions, the authors state that words and tags occurring fewer than 100 times are removed and that the data are then split into training, validation, and test sets. This wording suggests filtering before splitting, but it does not explicitly establish whether frequencies are counted over the whole corpus, a preliminary eligible subset, or only the training partition. The counting scope matters because it determines how the retained vocabulary and tag inventory are constructed and is necessary to reproduce the benchmark. Please state explicitly which data contribute to the frequency counts and describe the order of frequency counting, filtering, and partitioning. Please also provide the relevant reconstruction-script reference or pseudocode so that this preprocessing choice can be reproduced.

Paper locations: PDF page 4.

Suggested author response: Specify the corpus or partition used to count word and tag frequencies, clarify the order of counting, filtering, and splitting, and provide a reconstruction-script reference or pseudocode documenting these steps.

### 9. Clarify training targets and evaluation for records with multiple tags

In the model description and the YFCC100M tag-prediction experiment, please clarify how multiple retained tags associated with a record are converted into training targets. The supplied model text describes a label for each document and a softmax-based objective, while the tag-prediction setting permits multiple tags per record. The excerpts specify several preprocessing and training choices, but do not resolve whether training samples a tag, expands a record into separate record–tag examples, or combines losses across tags, nor how these targets are normalized or weighted. These choices determine each record's contribution to training and the interpretation of an epoch, and therefore matter for reproducibility and for interpreting the authors' accuracy and runtime comparisons. Please also clarify how records without retained tags are handled, which retained tags constitute the evaluation reference set, which records enter the precision-at-one denominator, and whether fastText and the linear Tagspace baseline use equivalent target processing and evaluation references. If these details already appear in the complete manuscript or associated implementation materials, a precise cross-reference and a concise protocol description would address the question.

Paper locations: PDF page 1; PDF page 2; PDF page 4.

Suggested author response: Provide or precisely cross-reference the multi-tag target-construction rule, its normalization or weighting, the training unit defining an epoch, the treatment of records without retained tags, the evaluation reference set and denominator, and the corresponding protocol used for the linear Tagspace baseline.

- Pending checks: For YFCC100M training, is one retained tag sampled per record, is each record expanded into separate tag targets, or is a loss computed over several tags?
