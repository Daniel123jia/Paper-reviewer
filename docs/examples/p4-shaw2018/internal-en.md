## Points Requiring Clarification

### 1. Clarify experimental conditions within paired position-representation comparisons

In the machine translation experiments and the main results table, were each absolute-position baseline and its corresponding relative-position model trained, selected, decoded, and evaluated under matched conditions? The authors explicitly state that they generated their own baselines to isolate the effect of relative position representations. The shared vocabulary, batching, optimization, and decoding descriptions, together with the configuration-specific training descriptions, provide substantial support for comparability. Please make this pairing explicit by confirming that the stated training duration, dropout, hardware allocation, and checkpoint policy applied to both position variants within each base or big configuration, and disclose any exceptions or additional development-set tuning, checkpoint-selection, or stopping decisions. Please also identify the exact BLEU scoring and output-processing settings and confirm that the absolute-position entries in the results table correspond to the newly generated baselines. Finally, explain how initialization and data ordering were handled and report any available evidence of variability across independent runs. These details would help readers assess how confidently the authors' reported BLEU differences can be attributed to the position representations, particularly for the smaller improvements.

Paper locations: PDF page 3; PDF page 4.

Suggested author response: Provide a concise paired-comparison statement or configuration summary confirming the shared conditions and documenting any exceptions, selection decisions, scoring settings, and baseline checkpoint provenance. Describe initialization and data-order handling, summarize available repeated-run evidence, and acknowledge uncertainty if such evidence is unavailable. Existing configuration records and evaluation documentation would be an appropriate response.

### 2. Clarify the efficiency baseline and measurement scope

In the implementation discussion and machine translation experimental setup, the authors describe tensor reshaping and representation sharing to limit computational and storage overhead, and report a 7% decrease in training steps per second while retaining the same model and batch sizes on P100 GPUs. The authors also state that they generated sinusoidal-position Transformer baselines to isolate changes in the library and experimental configuration. These explanations provide useful implementation and feasibility evidence, but the connection between that controlled baseline and the reported timing comparison is unclear. Please identify the timing comparator, dataset, and model configuration, and specify what operations the timing includes, the warmup and repetition protocol, and which execution conditions were matched. This information is needed to interpret the reported overhead and the scope of the practical efficiency claim. Please also identify any existing measurements of absolute runtime, peak memory, and scaling with sequence length, batch size, and representation sharing. Clarify which tensors and storage scope the stated complexity expressions cover and how these relate to the implemented configurations. If broader measurements are unavailable, please delimit the efficiency claim to the conditions actually measured.

Paper locations: PDF page 3; PDF page 4.

Suggested author response: Identify the timing baseline and experimental configuration; document timing boundaries, warmup, repetitions, and matched execution conditions; point to available absolute runtime, peak-memory, and scaling measurements; and explain the storage scope of the complexity statements. Where measurements are unavailable, qualify the practical efficiency claim to reflect the demonstrated scope.

### 3. Clarify whether the space analysis covers representation storage only

In the implementation subsection, the authors initially describe a reduction in the storage required for relative position representations through sharing across attention heads and sequences, then refer to the resulting bound as the “overall self-attention space complexity.” Does the surrounding text explicitly restrict this broader statement to representation storage? The opening qualification supports that interpretation, and the subsequent discussion explains how reshaping avoids broadcasting relative representations. However, the supplied excerpts do not establish whether the broader bound includes attention scores, normalized weights, or tensors retained during training. This distinction matters because reducing representation storage does not by itself specify the full memory requirements of self-attention. Please identify any existing qualification in the original text or make the scope explicit alongside the bound, stating which tensor storage is included and which is outside the analysis.

Paper locations: PDF page 2; PDF page 3; PDF page 4.

Suggested author response: Point to any existing text that explicitly limits the stated space bound to representation storage. If that limitation is intended but not explicit, clarify it alongside the bound and identify the included and excluded tensor storage.

### 4. Clarify the meaning and support for unseen-length generalization

In the discussion of relative position clipping, the authors state that clipping “enables the model to generalize to sequence lengths not seen during training.” Please clarify whether this refers to the representations remaining applicable at unseen lengths or to maintained translation performance at those lengths. The authors’ explanation that relative position representations are independent of total sequence length provides a rationale for architectural applicability. However, the described clipping-distance ablation reports aggregate development-set translation performance as the clipping distance varies; it does not isolate performance on sequences beyond the training-length range. This distinction matters because applicability at a new length does not by itself establish translation quality at that length. If architectural applicability is the intended claim, please make that scope explicit. If maintained translation performance is intended, please identify the relevant training-length boundary and point to evaluation beyond it, explaining how that evaluation supports the claim separately from the clipping-distance ablation.

Paper locations: PDF page 2; PDF page 3; PDF page 4; PDF page 5.

Suggested author response: Clarify the intended meaning of unseen-length generalization in the clipping discussion. If the claim concerns representational applicability, state that scope explicitly. If it concerns maintained translation performance, identify the training-length boundary and the supporting evaluation beyond that boundary; if such evidence is unavailable, qualify the claim accordingly.

The authors also explain that they generated baseline results to isolate the effect of relative position representations from other library and configuration changes. These details support the intended internal comparability, but the supplied passages and repository footnote do not uniquely identify the BLEU implementation and version, scoring tokenization, case handling, reference processing, or reconstruction of decoded word pieces. These choices matter for reproducing the reported improvements and interpreting comparisons with other results. Please provide the scorer and options, explain how hypotheses and references were prepared for scoring, and confirm that each baseline and relative-position comparison used identical processing and reference files. An identifiable library revision and evaluation command, or a precise pointer to existing documentation in the experimental setup, footnotes, or supplementary material, would help resolve this question.

Supply an identifiable tensor2tensor revision and evaluation command where available, or point precisely to existing documentation that establishes these details.

Please also state whether the observation is based on individual or repeated runs and explain what difference was considered a benefit, using any existing run-level results or variability information.
