# P1.1 structured reading acceptance (2026-11-04)

## Selection and compatibility

The candidate reading stream uses PyMuPDF's existing block coordinates, not a second production parser. It orders clear two-column bands left then right and places wide page bands by vertical position. PyMuPDF `find_tables()` supplies raw cells; equal-length multiline data cells are split into candidate rows. This choice keeps the original Evidence IDs and exact block coordinates for ordinary text, costs no new runtime dependency, and addresses the observed Shaw ordering and Table 3 layout. P1's offline comparison showed that PyMuPDF4LLM did not fix the selected Shaw heading order, while Docling was much slower and had no validated Evidence-ID mapping. Neither is installed into the production backend by P1.1.

`body[]`, upload parsing, Evidence API, PDF bytes/highlighting, review sampling/Prompt/countercheck and export code are unchanged. `reading_units[]` and section links are additive to the Source Bundle 1.0 response. No database migration or model call is introduced.

## Fixed-paper observations

The public Shaw PDF has SHA-256 `8086e2e5e139fd576631ce0ec4560c5ee66225bec260d631a3e8fe7f1f13d50b`. Tests compare selected landmarks from rendered pages, not the entire PDF. Fresh upload under PyMuPDF 1.28.2 produced 158 Evidence blocks and 167 reading units. The preexisting private snapshot produced 99 Evidence blocks and 110 reading units. In both, every original Evidence ID appears in at least one reading unit and the five selected headings occur in order: 3.2 → 3.3 → 4.1 → 4.2 → 4.3. The `sections[].reading_unit_ids` associations include the intervening body and carry across pages; these remain candidate boundaries. The old `body[]` order is unchanged.

Table 3's raw PyMuPDF matrix has two rows, with four data values stacked in each of three columns. P1.1's generic equal-line split yields four separate candidate rows: `Yes | Yes | 25.8`, `No | Yes | 25.8`, `Yes | No | 25.3`, `No | No | 12.5`. These agree with the selected human-visible reference, but the API status remains `detected_unverified` until an explicit human PDF reference is supplied for the requested task. A row maps to the intersecting original Evidence IDs and the table region, marked `source_block_partial`; the box is not an exact row highlight. Table 1 remains `structure_incomplete` because its caption has no detected table. A one-row uncaptioned candidate in Figure 1's area is `possible_false_positive` and is not used as a table reading unit. Figure 1's vector image remains `visual_review_required`; no table or raster box is attached to it.

Before table rows replace source blocks in `reading_units[]`, P1.1 now compares the complete whitespace-delimited source token multiset with the candidate table cells. A complete match emits only the structured rows. Any extra note, missing value, or unaccounted source text keeps the original Evidence blocks as reading units, emits no duplicate table rows, and sets `reading_unit_status=raw_evidence_fallback` with `uncovered_evidence_ids`. This check is for information preservation; it does not validate table semantics.

Number markers (1)–(5) are present at the selected pages/regions. Isolated number markers are grouped with horizontally adjacent expression fragments when geometry supports it; all formula transcripts remain unverified, and missing expression pieces are not silently reconstructed. The References region now follows the reconstructed heading order; the fresh snapshot has 27 candidate reference reading units, up from the legacy order's incomplete tail. This does not establish bibliography completeness.

The JMLR one-column PDF (SHA-256 `4ddf0066146f0644ba87d2462e9f73d3d72537d1daffb8d6ccc50840ff6c7dea`) retains its section sequence. TOC headings are linked only by exact canonical title on the same page; unmatched/duplicate headings remain unverified. Its wide performance table is detected but not marked as academically validated. The generated one-column PDF and an ambiguous cross-gutter fixture exercise uncomplicated order and conservative fallback. The blank-page fixture is `blocked` for text and formula tasks.

## P2 input gate

`assess_input_readiness(bundle, node, scope, reference)` supports `section_summary`, `formula_check`, `table_review`, and `figure_review`. Scope can narrow pages, sections, and a specific technical object. The production parse-quality API calls it without a human reference, so it cannot automatically declare a PDF ready.

| State | Rule | Example |
|---|---|---|
| `blocked` | Required text/object is missing or unreadable; a required technical object lacks structure; or an object/inventory human reference is absent. | Scanned blank page; undetected equation; Table 1 structure; unverified formula check. |
| `needs_review` | Text exists but geometry, section assignment, source map, page inventory, or human reading reference is unresolved. | Shaw whole-paper section summary; ambiguous gutter block. |
| `ready` | The scoped source units and required object/page inventory are explicitly attested by a `human_pdf_review` reference with an ID; no blocking condition remains. | Selected Table 3 rows with the fixed visual reference; short synthetic section summary after checking its sole page. |

The human reference is an internal input to the gate, not a new public endpoint or persistent approval database. P2 must define who supplies and records that reference and how corrected visual transcripts enter the workflow. A `ready` decision is scoped to its node and materials; it is not a claim that the entire paper was parsed correctly.

For `scope.object_ids`, the gate requires every requested object ID to resolve exactly once within the same Source Bundle document, selected pages and selected sections. A partial match, foreign object or table in raw-evidence fallback is `blocked` even when the supplied human reference names the other objects.

## Remaining limits

- Geometric columns can fail on unusual layouts. Cross-gutter ambiguity is marked `unverified`; math fragments and full-width objects still need visual checks.
- Equal-line table splits can misread legitimate multiline cells. Row alignment is a candidate, and Table 1 remains unavailable as structured data.
- Figure semantics and vector region boundaries are not parsed. Formula grouping does not verify mathematical transcription.
- The existing PDF highlight API has exact coordinates only for original Evidence blocks. Table row units have a larger source region until an exact row anchor is validated.
- Full-review input is not yet accepted as reliable. P2 remains gated on review policies and human reference provenance from ChatGPT's next-stage design.
